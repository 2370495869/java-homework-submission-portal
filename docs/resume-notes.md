# 简历与面试要点

本文只总结仓库中已实现的能力；它不代表系统已在生产环境部署或经过真实用户验证。

## 简历表述

- 实现 Java 21 / Spring Boot 4 课程作业平台，支持账户角色、课程邀请码、作业截止策略以及带时间和迟交状态的提交版本。
- 使用 Spring Security、BCrypt、CSRF 与课程归属校验保护页面及文件下载；通过文件签名检查、随机存储键、大小限制和独立文件卷处理作业附件。
- 采用 PostgreSQL 与 Flyway 管理持久化数据，提供 Docker Compose 部署、Maven Wrapper 和 GitHub Actions 自动构建。

## 面试讨论

### 授权如何覆盖页面与业务数据？

Spring Security 在请求入口限制角色，课程、作业和下载服务再校验教师是否拥有课程、学生是否已加入课程或拥有提交。这样即使用户猜到其他记录的 ID，也需要通过业务归属检查。

### 为什么上传文件名不作为磁盘路径？

原始文件名只作为展示元数据保存。扩展名和文件头做基础一致性检查，磁盘文件使用随机键；存储层限制大小、拒绝覆盖并计算 SHA-256。下载时按提交记录重新检查访问者权限。签名检查不等于完整解析或恶意软件扫描，项目也没有声称提供病毒检测。

### 数据库事务与文件卷如何配合？

文件写入与关系数据库不能共享一个原子事务。当前流程先写文件，再在数据库事务中记录提交；数据库记录失败时尝试删除刚写入的文件，并把清理失败作为附加异常保留。这个补偿路径降低孤儿文件风险，但不等同于跨系统事务。

### 如何解释测试边界？

本机 `verify` 使用 H2 覆盖应用、迁移和业务测试；PostgreSQL Testcontainers 测试需要 Docker。本机没有 Docker 时它会跳过，因此不能把本机结果描述为 PostgreSQL 容器验证。GitHub Actions 曾成功运行 `verify`，见 [实现报告](implementation-report.md) 的带日期记录。

## 当前限制

- 文件类型校验是基础签名校验，没有恶意软件扫描或完整文档解析。
- 尚未实现密码找回、登录限速、评分/评论或对象存储适配器。
- 仓库没有附带开源许可证；公开可见不等于获得再分发或商用授权。
- PostgreSQL Testcontainers 与 Docker Compose 需在有 Docker 的环境单独验证。
